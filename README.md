# 科研论文解读 Skill（paper-interpretation）

> 把一个“读论文”的模糊请求，变成一套可复用、可核查的深度解读流程。
> **只基于论文原文与其参考文献下结论，绝不编造文献、数据或基线。**

## 这是什么

`paper-interpretation` 是一个用于科研论文精读与批判性评估的 Skill。它不满足于复述摘要，而是按固定框架逐层追问：作者真正想解决什么问题、方法依赖哪些未言明的假设、创新到底发生在哪一层、实验证据是否足以支撑结论、结论在什么条件下会失效、审稿人会怎样质疑，以及还能往哪些方向延伸。

适用于论文精读、组会准备、文献汇报、审稿训练和选题调研。

## 核心能力

- **四类输入、如实降级**：全文 PDF、正文文本、仅摘要、标题/DOI/链接；材料不足时明确标注“推测/待证”，不补全缺失的实验或数据。
- **三档深度**：一屏概览、标准深析、审稿级深析，按需切换。
- **七个固定维度**：每次输出结构一致，便于横向比较不同论文。
- **审稿级审查**：逐节质疑、可复现性审计、最强基线逐项对照、作者反驳预判、投稿倾向判断。
- **组会汇报大纲**：可直接对接 paper-ppt skill 生成逐页汇报文档。
- **结果落盘**：解读报告自动保存为 Markdown，避免会话关闭后丢失。
- **无视觉兜底**：模型无法读图时，改用图注、正文描述和表格数字，并明确标注“未目视核对”。

## 三档解读模式

| 档位 | 触发方式 | 输出内容 |
|---|---|---|
| 档1 快速概览 | “快速”“概览”“一句话” | 约一屏：问题意识、方法一句话、核心结论、1–2 个亮点与最可疑点 |
| 档2 标准深析（默认） | 不指定，或“解读一下” | 按七个维度完整走一遍 |
| 档3 审稿级深析 | “深入”“审稿”“严查”“全面” | 档2 + 逐节质疑、可复现性审计、最强基线对照、反驳预判、投稿倾向（接收/弱接收/弱拒绝） |

## 七个分析维度

1. **真实的问题意识**：区分作者声称的问题、实际解决的问题、领域位置，以及没有这篇论文时已有方法卡在哪里。
2. **默认前提与隐含假设**：从数据、方法、任务、实验、应用五个角度，区分明说、未说但依赖、可能导致结论失效的假设。
3. **真实创新点**：改了哪些环节、引入了什么、为什么可能有效、属于概念/技术/工程哪一层、与最相关方法的差异。
4. **证据是否支撑结论**：直接/间接证据、缺失的 baseline 与消融、数据集与指标偏向、提升是否显著。
5. **可能的失效场景**：换数据、换任务、噪声更大、样本更少、分布漂移、更强基线、真实应用中的反例。
6. **审稿人视角的总体评价**：问题重要性、创新性、方法合理性、实验充分性、基线公平性、结论是否夸大、可复现性、写作逻辑。
7. **可扩展的研究方向**：方法、数据、任务、理论、实验、应用六个方向，给出 5 个可执行的研究想法。

## 安装

### 环境要求

- 支持 Skill 的 ZCode 客户端
- Python 3.8+
- PyMuPDF（用于 PDF 文本、参考文献和图注提取）

```bash
pip install pymupdf
```

### 用户级安装（所有项目可用）

```bash
git clone https://github.com/aida-333/paper-interpretation-skill.git \
  ~/.zcode/skills/paper-interpretation
```

### 项目级安装（仅当前项目可用）

```bash
mkdir -p .zcode/skills
git clone https://github.com/aida-333/paper-interpretation-skill.git \
  .zcode/skills/paper-interpretation
```

> 目录名 `paper-interpretation` 与 `SKILL.md` frontmatter 中的 `name` 保持一致。

## 使用

直接把论文和诉求一起交给 Agent：

```text
帮我标准深析这篇论文：D:/papers/xxx.pdf
```

```text
审稿级解读这篇论文，重点看实验是否支撑结论：
https://arxiv.org/abs/xxxx.xxxxx
```

```text
快速概览一下这篇论文的摘要：<粘贴摘要>
```

### 组会汇报

```text
基于这篇论文做一份组会汇报大纲，标准版 15–20 页
```

需要完整逐页汇报文档时，Skill 会建议使用配套的 paper-ppt skill；只需要大纲时，会额外输出 `<论文短标题>_汇报大纲.md`。

## 输出约定

- 解读结果保存为 `<论文短标题>_解读.md`，与论文放在同一目录。
- 固定骨架：论文信息 → 七个维度 → 一句话总结 + 最该记住的 3 点。
- 所有超出原文的推断标注“（推测）”或“（需查证）”。
- 引用参考文献编号前，先核对文末条目；原文缺失的条目标注“原文未列明该参考文献”。

## 设计铁律

1. 只基于原文与参考文献；原文没有的写“论文未提及，需外部查证”。
2. 证据不足时明确说“无法基于现有材料判断”，不编答案。
3. 真实优先于数量：失效场景通常 3–5 条，凑不出就少列并说明原因。
4. 区分事实与推测，所有推断显式标注。
5. 仅在判断重要性、新颖性、更强基线时联网，并注明 URL/DOI 与访问日期。
6. 参考文献引用必须核对到条目。

## 适用与不适用

**适合**：论文精读、组会/文献汇报准备、审稿训练、选题调研、判断一篇论文是否值得跟进。

**不适合**：替代领域专家的最终判断；在只有标题或摘要时给出确定性的实验评价；把解读当作论文事实本身——它始终是“基于材料的分析”，不是原论文。

## 配套 Skill

- **paper-ppt**：把本 Skill 的解读结论转成逐页汇报文档（封面、研究背景、方法原理、实验评估、总结展望）。未安装时，本 Skill 仍可单独输出汇报大纲。
